### Phase 1: Deep-Dive Audit (Concurrency, State Machines & Extreme Edge Cases)
Once the cross-platform port is verified and compiles on Windows, audit the entire system against the following extreme edge cases and architectural bottlenecks:

1. **Multi-Session `libtorrent` Mechanics & Alert Loop Starvation**:
   - **Alert Queue Overflow**: Check if `pop_alerts()` across multiple sessions risks hitting `alert_queue_size_limit` under burst traffic. Ensure zero blocking I/O or heavy CPU parsing occurs inside the tight alert polling loop.

   - **Bootstrap & Routing Table Persistence**: Audit how multiple sessions save/load their DHT state (`save_state` / `load_state`) and whether their Node IDs or bootstrap timings collide.
2. **Concurrency, Lock Contention & Backpressure**:
   - Audit the data flow from multiple `libtorrent` sessions + the C++/HTTP Tracker into the processing queues.
   - Check for unbounded in-memory queues/sets (e.g., `info_hash` deduplication caches) that could cause OOM after weeks of uptime. Verify bounded LRU/TTL structures or Bloom filters.
   - Check thread/async/IPC boundaries for race conditions or deadlocks.
3. **SQLite High-Concurrency & WAL Starvation**:
   - Audit how writes from multiple sessions and the tracker are serialized into SQLite.
   - Check for potential `SQLITE_BUSY` / `database is locked` exceptions under burst writes (note that Windows file locking semantics on SQLite WAL files are stricter than Linux!).
   - Verify PRAGMA settings (`journal_mode=WAL`, `synchronous`, `busy_timeout`) and prevent **WAL Checkpoint Starvation** (unbounded `.wal` file growth).
4. **HTTP Tracker Edge Cases (`tracker_server.cpp`) & Protocol Poisoning**:
   - Audit the C++ HTTP tracker against buffer overflows, malformed `info_hash` / `peer_id` query parameters (non-20-byte lengths, broken URL-encoding), oversized payloads, socket descriptor leaks on half-open connections, and malformed bencode generation.
5. **Graceful Shutdown & Cross-Platform Signal Handling**:
   - Ensure signal handling works identically on Windows (`SetConsoleCtrlHandler` / `SIGINT` / `SIGBREAK`) and Linux (`SIGINT` / `SIGTERM`), cleanly stopping the C++ tracker, flushing all pending queues to SQLite, and persisting all `libtorrent` session states without hanging or corrupting files.
